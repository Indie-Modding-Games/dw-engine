# assets

Contenido del juego por paquetes ([tubería de assets](../../docs/architecture/assets-pipeline.md)). `AssetId` es el nombre estable de un asset (`digimon/agumon/model`) y `PackManifest` lee el `pack.yaml` de cada paquete: id, versión, capa, prioridad y dependencias. El formato del manifiesto también está en [`content/schemas/pack.schema.json`](../../content/schemas/pack.schema.json). `findPacks` encuentra los paquetes de una carpeta de contenido (carpetas y archivos `.pak`), `openPacks` abre los archivos y `VirtualFileSystem` los monta, los apila por capa y prioridad y dice qué fichero gana para cada ID. Lee los ficheros a través de `FileSystem`: `DiskFileSystem` para el disco, `PakFileSystem` para un [archivo `.pak`](../../docs/formats/pak.md) (que `writePak` escribe) y `MemoryFileSystem` para los tests; cada paquete se monta con el suyo (`PackLocation`). Solo depende de `core`. `decodePng` decodifica un PNG a RGBA de 8 bits con lodepng, para las texturas que lee el motor (el visor de assets del overlay de depuración, por ahora), e `inspectPng` lee solo su cabecera. `decodeOpus` decodifica un [Ogg Opus](../../docs/formats/opus.md) de `dwx cook` a PCM de 16 bits con libopus, con un lector de páginas Ogg propio. Los `.pak` de versión 2 se descomprimen con zstd. `decodeKtx2` lee las texturas cocinadas ([KTX2 con UASTC](../../docs/formats/ktx2.md)) con libktx y las transcodifica a BC7, o a RGBA de 8 bits si la GPU no muestrea BC7. `openAsset` abre los bytes de un asset con el lector del motor para su tipo (PNG, glTF/GLB con cgltf, YAML, y las cabeceras de WAV, SF2, MIDI e Y4M) y `checkContent` lo hace con todos los assets de una pila: es la prueba de que el motor carga lo que hay en un paquete (`dwe-game --check-content <carpeta>`, `dwx validate`). `readModel` resume un glTF: ficheros externos, padres de las articulaciones de cada skin y nombres de las animaciones.
